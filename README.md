# TeachingWorkloadSystem · 教学工作量核算系统

基于 **Python、Django 和 SQLite** 的教学工作量管理项目，使用 Django Admin 提供中文管理界面，支持课堂教学、实践环节和实验教学的数据录入、自动核算及 Excel 报表导出。

项目将教学工作量规则封装在业务模型中，将数据管理、条件筛选和导出操作集中在管理后台，适合教学管理场景的原型开发与课程实践。

> 本文依据当前仓库代码编写。系统入口为 Django Admin；目前没有独立教师前端或 REST API。完整的需求与设计说明见 [实验报告](实验报告.md)，其中部分设计目标仍需进一步实现。

## 功能概览

| 模块 | 当前功能 |
| --- | --- |
| 基础信息 | 管理组织机构、教师档案、课程、班级与教学地点 |
| 系数规则 | 配置课程类别与人数区间系数、实习指导系数及补贴天数、实验难度系数 |
| 课堂与公选课 | 记录计划学时、班级、人数、考核方式、开新课、双语及上机信息 |
| 实践环节 | 支持实习、课程设计、毕业设计（论文）和上机实习 |
| 实验教学 | 记录实验项目、发生地、难度、批次、学时、班级数及补贴 |
| 自动计算 | 保存工作量记录时计算并存储核算结果 |
| 附件校验 | 开新课要求上传凭证，上机实习要求上传上机卡扫描件 |
| 数据管理 | 按各列表提供的学期、状态、类别等条件筛选，部分列表支持关键词搜索 |
| 数据导入导出 | 部分模型通过 django-import-export 提供导入导出入口 |
| Excel 报表 | 单独导出课堂、实践、实验、公选课报表；按组织生成六类工作表 |

## 本地运行

### 1. 获取项目并创建虚拟环境

建议使用 Python 3.12：

```bash
git clone https://github.com/1124W/TeachingWorkloadSystem.git
cd TeachingWorkloadSystem
python -m venv .venv
```

Windows PowerShell：

```powershell
.\.venv\Scripts\Activate.ps1
```

macOS / Linux：

```bash
source .venv/bin/activate
```

### 2. 安装依赖

```bash
python -m pip install --upgrade pip
python -m pip install "Django==5.1.4" django-import-export openpyxl
```

Django 5.1.4 为原项目版本，正式部署前应升级至仍受支持且已验证兼容的版本。需要使用导入导出的特定文件格式时，可按 django-import-export 的要求补充相应格式依赖。

### 3. 调整当前配置中的导入顺序

当前 `workload_system/settings.py` 在使用 `os.environ` 之后才导入 `os`，直接启动会出现 `NameError: name 'os' is not defined`。

请将文件底部的 `import os` 移至文件顶部，与 `Path` 导入放在一起，确保它位于 `SECRET_KEY` 定义之前：

```python
import os
from pathlib import Path
```

配置已经支持从 `DJANGO_SECRET_KEY` 环境变量读取密钥；未设置时使用开发用默认值。本地演示之外的环境应配置独立密钥。

### 4. 初始化数据库并启动

仓库已包含迁移文件，首次运行直接执行迁移即可：

```bash
python manage.py check
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

浏览器访问：**http://127.0.0.1:8000/admin/**

使用刚创建的超级管理员账号登录。访问首页 http://127.0.0.1:8000/ 也会自动跳转至后台。

## 首次使用流程

仓库没有提供演示数据库或预置系数，需要先录入基础数据。

1. **创建基础信息**：添加组织机构、教师、班级，以及需要使用的课程与教学地点。
2. **配置规则**：根据实际核算办法填写人数区间系数、实习指导系数与实验难度系数。人数系数区间应避免重叠。
3. **关联教师账号**：需要以教师身份使用时，创建 Django 用户并将其关联至教师档案。
4. **录入工作量**：选择教师和班级，填写学期、学时或天数等字段，按要求上传附件。
5. **检查核算结果**：保存记录后查看“核算工作量”，按下文计算规则进行核对。
6. **维护审核状态**：管理员可在记录表单中维护“待审核 / 已审核 / 驳回”状态。
7. **导出报表**：在工作量列表勾选记录，选择对应导出操作；或在组织机构列表选中组织，使用六合一导出。

选择班级关联不会自动回填工作量记录中的学生人数、自然班级数或实验班级数，录入时需保持这些字段一致。

### 账号与权限

- 超级管理员用于初始化和管理全部数据。
- 普通用户进入后台需要启用 `is_staff`，并分配相应的模型权限；关联教师档案后，工作量列表会按当前教师过滤。
- 工作量管理代码识别 `TeachingAdmin` 和 `CollegeAdmin` 两个组名；这些组需要手动创建，并另外配置 Django 模型权限。
- 两个管理组当前均可查询全部工作量，尚未实现按所属学院隔离。
- 普通教师查看已审核记录时，后台表单字段会设为只读。

当前权限实现仍需完善。特别是导入、删除、审核状态变更等入口，应在正式使用前逐项验证权限边界。

## 工作量计算规则

计算实现位于 [core/models.py](core/models.py)。以下公式描述当前代码行为，实际业务使用前应与学校核算办法逐项核对。

### 课堂与公选课

设：

- `H`：计划学时。
- `C = min(自然班级数, 4)`：用于计算的班级数。
- `K`：按课程类别和学生人数匹配的人数系数；未匹配到规则时默认 `1.0`。

```text
基础工作量 = (H + 考试补贴学时) × K × C

总工作量 = 基础工作量
         + 上机学时 × 0.7 × C       （含上机时）
         + H × 0.5                 （开新课时）
         + H × 0.5                 （双语教学时）
```

考试课补贴为 2 学时，考查课为 0；开新课与双语增量分别计算，可同时叠加。结果保留两位小数。

例如：计划 32 学时、考试课、1 个自然班、人数系数为 1，无上机、开新课或双语教学，则工作量为 `(32 + 2) × 1 × 1 = 34`。

### 实践环节

| 类型 | 当前计算公式 |
| --- | --- |
| 上机实习 | 机时 × 自然班级数 × 0.7 |
| 课程设计 | 计划天数 × 自然班级数 × 3.3 |
| 实习 | （计划天数 + 规则补贴天数）× 自然班级数 × 指导系数 |
| 毕业设计（论文） | 计划周数 × 学生人数 × 类别系数 |

毕业设计类别系数：理工类 `1.3`、文法经管类 `1.1`、教师教育类 `1.2`；未指定时按 `1.0` 处理。实习类型未关联指导规则时，当前计算结果为 `0`。

### 实验教学

```text
实验当量 = 难度系数 K × 批次系数 P × 学时数 × 班级数
总工作量 = 实验当量 × 0.8 + 补贴
```

1～5 批的批次系数依次为 `1.3、2.0、2.6、3.0、3.4`。结果保留两位小数。

修改系数表不会自动重新计算历史记录，记录再次保存时才会按当前规则计算。

## Excel 导出

业务列表提供以下独立报表：

- 表2：课堂教学核算表。
- 表3：实践环节核算表。
- 表4：实验工作量计算表。
- 表5：公选课核算表。

组织机构列表中的六合一操作会为每个选中组织生成学院汇总、课堂教学、实践环节、实验工作量、公选课、教师汇总六类工作表。

**导出前需注意当前口径：**

- 学院、教师汇总按已审核记录统计；六合一明细表会包含该组织的其他审核状态记录。
- 六合一导出没有学期过滤，会读取所选组织的历史记录。
- 部分表头固定为“江苏大学京江学院”和“2025年度”，更换使用单位或年度需修改 `core/admin.py`。
- 部分导出模板说明与模型公式仍需统一，尤其是实验补贴的计算口径；请以模型公式核对数值。

## 当前限制与后续改进

- **审核入口**：代码定义了批量通过、驳回动作，但三个具体工作量后台类的 `actions` 被各自的导出动作覆盖，目前没有完整开放这两个批量审核入口。
- **汇总口径**：学院汇总的部分分类栏位仍使用占位值；校外实践分类使用的字符串条件与现有类型枚举不一致，需要修正后再用于正式核算。
- **规则维护**：部分系数可配置，但课程设计、毕业设计、批次等系数仍写在代码中。
- **数据校验**：附件必填规则通过模型 `clean()` 实现；通过脚本或其他入口写入时需显式执行校验，不能仅依赖 `save()`。
- **工程配置**：尚未提供依赖锁定文件、预置数据和完整自动化测试；`core/tests.py` 目前为占位文件。

后续可优先补充计算规则与权限测试，完善审核流程、按学院的数据隔离、导出筛选及历史核算规则追溯。
